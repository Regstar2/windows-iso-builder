# Windows ISO Builder v1.0.0 — Stable release

## Highlights

Windows ISO Builder v1.0.0 is the first stable release of the GUI and PowerShell client for building Windows 10/11 ISO images through UUP dump. It consolidates the validated pre-1.0 baseline and the final fixes discovered during real Windows 11 25H2 end-to-end validation.

## Main features

- WPF GUI over the existing PowerShell backend;
- dynamic UUP dump catalog without hardcoded Windows release/build catalogs;
- Windows 10/11, recommended build, and full Catalog;
- language, edition, multi-edition, WIM/ESD, and converter option selection;
- structured preflight before UAC;
- elevated build, progress, cancellation, logs, result actions, and result SHA-256;
- RU/EN localization, English fallback, System/Light/Dark theme;
- sanitized diagnostics bundle;
- GitHub Issue Forms and in-app feedback;
- Stable/Prerelease update discovery through official GitHub Releases;
- global Network Policy: System, Direct, Custom HTTP, Custom SOCKS5;
- DPAPI CurrentUser for saved proxy passwords;
- fail-closed Custom proxy mode and loopback bridge for the generated downloader/aria2.

## Final release hardening

Real E2E validation found several release blockers that are fixed in v1.0.0:

- requested ESD output now produces `sources\install.esd`, and WIM/ESD mismatches fail with `ISO_VALIDATION_FAILED`;
- Windows PowerShell 5.1 five-field form POST compatibility is fixed;
- Cleanup is OFF by default while remaining available as explicit opt-in;
- integrated updates are also OFF by default after a measured 1:42:45 E2E build; integration remains available in Advanced options and is explicitly described as potentially expensive;
- a passive activity indicator keeps long quiet backend phases visibly alive without changing determinate progress semantics;
- the Win32 ICO resource is repaired and regression validation is stricter;
- converter detail logs use ISO-8601 timestamps for performance diagnosis.

ApplicationVersion remains `1.0.0`, PowerShell ModuleVersion remains `0.3.0`, and Backend Contract / BuildPlan schema versions remain `1`.

## Two download formats

The release is published in two forms:

1. `windows-iso-builder-v1.0.0.zip` — the complete portable package with GUI, PowerShell CLI/backend, and documentation. This is the recommended option for CLI use, diagnostics, and transparent access to package contents.
2. `windows-iso-builder-v1.0.0.exe` — a single self-extracting launcher. It embeds the same validated portable payload, extracts it to `%TEMP%`, launches the GUI, and performs best-effort cleanup after exit.

Both formats use the same PowerShell backend; the standalone EXE does not introduce a second ISO build implementation.

## Requirements

- Windows 10/11 x64;
- access to UUP dump and Microsoft CDN;
- enough disk space for UUP cache, work directory, and the ISO;
- UAC only for the privileged build stage;
- no separate .NET Runtime is required for the portable ZIP;
- .NET 10 SDK is required only when building from source.

## Quick start

### Standalone EXE

1. Download `windows-iso-builder-v1.0.0.exe` and its `.sha256` file.
2. Verify SHA-256.
3. Run the EXE as a normal user.

### ZIP with GUI + CLI

1. Download `windows-iso-builder-v1.0.0.zip` and its `.sha256` file.
2. Verify SHA-256 and fully extract the ZIP.
3. Run `WindowsISOBuilder.exe` for the GUI.
4. Use `Start-Builder.cmd` or the PowerShell entrypoint for CLI usage.

In the GUI, choose Windows, language, editions, WIM/ESD, and output directory, run preflight, then choose Create ISO. Integrated updates are available in Advanced options and are disabled by default.

## Network / proxy

Network settings are available in `Settings -> Network`.

- System uses Windows/.NET system proxy behavior.
- Direct explicitly bypasses proxies.
- Custom HTTP uses the configured HTTP proxy.
- Custom SOCKS5 uses SOCKS5 through a local loopback bridge.

Custom mode fails closed: configuration, credential, or connection failures do not become a silent Direct fallback. For the generated downloader/aria2 path, upstream proxy host/user/password are not placed on the command line.

## Security

The application contains no GitHub PAT/OAuth token, does not disable UAC/antivirus, and does not self-update. Diagnostics are created manually, use an allowlist and sanitizer, and should still be reviewed before publishing.

Proxy passwords are not stored in `network.json`, BuildPlan, backend request, command line, logs, diagnostics, or release artifacts. Saved credentials are protected with Windows DPAPI CurrentUser.

## Checksum verification

```powershell
$files = @(
    '.\windows-iso-builder-v1.0.0.zip',
    '.\windows-iso-builder-v1.0.0.exe'
)

foreach ($file in $files) {
    $artifact = Resolve-Path $file
    $checksumFile = Resolve-Path "$file.sha256"
    $actual = (Get-FileHash -Algorithm SHA256 -LiteralPath $artifact).Hash.ToUpperInvariant()
    $expected = ((Get-Content -LiteralPath $checksumFile -Raw).Trim() -split '\s+')[0].ToUpperInvariant()
    if ($actual -ne $expected) { throw "Release SHA-256 mismatch: $file" }
}
```

## Known limitations

- There is no automatic self-update: the app only opens the official GitHub release page.
- Integrating updates can substantially increase build time, especially for ESD, so it is opt-in.
- The single EXE temporarily extracts its embedded portable runtime when launched; it is a launcher, not a separate backend.
- Installer/MSIX, USB writer/Rufus integration, History/Profiles, customization, debloat, unattended setup, driver injection, TPM bypass, activation, accounts/cloud sync, telemetry, and plugins are outside v1.0.0.
