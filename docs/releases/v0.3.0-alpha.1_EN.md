# Windows ISO Builder v0.3.0-alpha.1 — GUI MVP

Date: 2026-08-18

## Overview

`v0.3.0-alpha.1` introduces the first Windows GUI on top of the stabilized PowerShell backend. The backend is not rewritten: the WPF client uses only `Invoke-WibBackend.ps1`, Backend Contract Schema v1, and BuildPlan Schema v1.

## Added

- C# / .NET 10 WPF GUI targeting `net10.0-windows`;
- Quick Mode for Windows 11/10 through backend `GetRecommendedBuild`;
- Catalog Mode through `SearchBuilds`, architecture, Preview, and a servicing-record display filter;
- explicit activation of a selected Catalog row without starting metadata work on a single click;
- dynamic languages and editions from the backend;
- multi-edition selection, ESD/WIM, and existing build options;
- `CreateBuildPlan` and preflight UX;
- asynchronous `ExecuteBuildPlan` plus a byte-safe incremental NDJSON event reader;
- cooperative cancellation through `CancelBuild`;
- success/error/cancelled states, log/folder actions, and SHA-256 copy;
- explicit mappings for the stable backend error taxonomy;
- best-effort GUI logging under `%LOCALAPPDATA%\WindowsISOBuilder\logs` without copying backend exception messages into the log;
- C# unit/integration tests with `Microsoft.NET.Test.Sdk`;
- `tools/Build-Gui.ps1`;
- self-contained `win-x64` publishing and headless packaged `WindowsISOBuilder.exe --backend-smoke`;
- a self-hosted Windows validation workflow;
- RU/EN GUI architecture documentation.

## Compatibility

- ApplicationVersion: `0.3.0-alpha.1`;
- PowerShell ModuleVersion: `0.3.0`;
- Backend Contract SchemaVersion: `1`;
- BuildPlan SchemaVersion: `1`;
- the GUI handshake requires both Contract v1 and BuildPlan v1 without requiring exact ApplicationVersion matching;
- `Start-Builder.cmd`, `Start-Builder.ps1`, TUI, and CLI remain supported;
- the GUI runs as `asInvoker`; elevation remains owned by the backend.

## Architecture and security boundary

The GUI does not import the PowerShell module directly, invoke private functions, parse `Write-Host`, transcripts, aria2/converter output, or manage the aria2/DISM process tree.

Packaged backend code is resolved relative to the executable; ambient environment variables cannot replace executable `Invoke-WibBackend.ps1`. The self-hosted workflow runs only same-repository PR code and does not execute fork PR code on the owner-controlled runner.

Failures are classified by `error.code`. The final Backend response remains authoritative; malformed/unknown progress telemetry cannot complete or fail a build.

## Package

The release ZIP contains a self-contained `win-x64` GUI together with the existing PowerShell backend/TUI/CLI. End users do not need a separately installed .NET Runtime. Release builds suppress PDB output and `.pdb` is also denied by package safety policy. `.github`, tests, and validation artifacts are not release-package content. No installer/MSIX is added in this release.

## Validation status

`.github/workflows/windows-self-hosted-validation.yml` runs `Invoke-ReleaseValidation.ps1 -Full` on the Windows self-hosted runner and uploads `validation-result.json` as an artifact.

Earlier self-hosted runs exposed and enabled fixes for the WPF/WinForms `Application` collision, missing `System.IO`/test usings, and incomplete MSTest runner configuration. Those historical runs do not validate the current head.

## Out of scope

History, profiles, queue, cache-management UI, updater, installer/MSIX, USB/Rufus integration, full theme/language settings, account/cloud features, Windows customization/debloat, drivers, TPM bypass, activation, and a custom downloader/converter. GitHub Actions is used only for owner-controlled self-hosted validation and is not runtime functionality.
