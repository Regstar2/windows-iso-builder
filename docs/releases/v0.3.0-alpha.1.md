# Windows ISO Builder v0.3.0-alpha.1 — GUI MVP

Дата: 2026-08-18

## Главное

`v0.3.0-alpha.1` добавляет первый пользовательский Windows GUI поверх стабилизированного PowerShell backend. Backend не переписан: WPF-клиент использует только `Invoke-WibBackend.ps1`, Backend Contract Schema v1 и BuildPlan Schema v1.

## Добавлено

- WPF GUI на C# / .NET 10 (`net10.0-windows`);
- Quick Mode для Windows 11 и Windows 10 через backend `GetRecommendedBuild`;
- Catalog Mode через `SearchBuilds` с архитектурой, Preview и display-фильтром servicing records;
- явная активация выбранной Catalog row без metadata-запросов по одиночному клику;
- динамические языки и редакции из backend;
- multi-edition выбор, ESD/WIM и существующие build options;
- `CreateBuildPlan` и отдельный preflight UX;
- асинхронный `ExecuteBuildPlan` с byte-safe incremental NDJSON event reader;
- cooperative cancellation через `CancelBuild`;
- success/error/cancelled states, открытие журналов/папки и копирование SHA-256;
- mapping стабильной backend error taxonomy;
- best-effort GUI logging в `%LOCALAPPDATA%\WindowsISOBuilder\logs` без копирования backend messages в log;
- C# unit/integration test project с `Microsoft.NET.Test.Sdk`;
- `tools/Build-Gui.ps1`;
- self-contained `win-x64` publish и headless package smoke `WindowsISOBuilder.exe --backend-smoke`;
- self-hosted Windows validation workflow;
- GUI architecture documentation RU/EN.

## Совместимость

- ApplicationVersion: `0.3.0-alpha.1`;
- PowerShell ModuleVersion: `0.3.0`;
- Backend Contract SchemaVersion: `1`;
- BuildPlan SchemaVersion: `1`;
- GUI handshake требует одновременно Contract v1 и BuildPlan v1, но не требует точного совпадения ApplicationVersion;
- существующие `Start-Builder.cmd`, `Start-Builder.ps1`, TUI и CLI сохранены;
- GUI запускается как обычный пользователь (`asInvoker`), elevation остаётся ответственностью backend.

## Архитектурная и security граница

GUI не импортирует PowerShell module напрямую, не вызывает private functions, не парсит `Write-Host`, transcript, aria2/converter output и не управляет aria2/DISM/process tree самостоятельно.

Packaged backend определяется относительно executable; ambient environment variable не может подменить исполняемый `Invoke-WibBackend.ps1`. Self-hosted workflow запускается для same-repository PR и не исполняет fork PR code на owner-controlled runner.

Типы ошибок определяются по `error.code`. Final Backend response остаётся authoritative source of truth; malformed/unknown progress telemetry не завершает и не проваливает build.

## Release package

Пользовательский ZIP должен содержать self-contained `win-x64` GUI вместе с существующим PowerShell backend/TUI/CLI. Установка отдельного .NET Runtime пользователю не требуется. Release build не публикует PDB, а `.pdb` дополнительно запрещён package safety policy. `.github`, tests и validation artifacts в пользовательский ZIP не входят. Installer/MSIX в этой версии отсутствует.

## Validation status

Для PR используется `.github/workflows/windows-self-hosted-validation.yml`, который запускает `Invoke-ReleaseValidation.ps1 -Full` на Windows self-hosted runner и сохраняет `validation-result.json` как artifact.

Предыдущие self-hosted прогоны уже выявили и позволили исправить WPF/WinForms `Application` collision, missing `System.IO`/test usings и неполную MSTest runner configuration. Эти исторические прогоны не считаются PASS текущего head.

**Full validation текущего head: PENDING / QUEUED до фактического выполнения runner.**

Manual GUI smoke: **NOT RUN**.

Real GUI E2E Windows 11 x64 ru-RU Professional ESD: **NOT RUN**.

## Не входит в версию

History, profiles, queue, cache-management GUI, updater, installer/MSIX, USB writer/Rufus, full theme/language settings, account/cloud features, Windows customization/debloat, drivers, TPM bypass, activation и custom downloader/converter. GitHub Actions используется только для owner-controlled self-hosted validation и не является частью runtime.
