# Windows ISO Builder v0.2.2-alpha.1 — Reliability & Control

Date: 2026-08-18

## Purpose

`v0.2.2-alpha.1` is the second architecture release before a GUI. It does not add a GUI and does not change Backend Contract or BuildPlan SchemaVersion. The goal is to make the existing backend predictable enough for a frontend to diagnose the environment before UAC and safely cancel a long build.

## Versions

- ApplicationVersion: `0.2.2-alpha.1`;
- ModuleVersion: `0.2.2`;
- Backend Contract SchemaVersion: `1`;
- BuildPlan SchemaVersion: `1`.

## Preflight

A reusable `Invoke-WibPreflight` engine is shared by `RunPreflight` and real build execution.

Local checks cover Windows/x64/PowerShell, required tools, cache/output path/write probes, and conservative 40 GiB/8 GiB disk minimums. Missing `Mount-DiskImage` is a warning. The optional online check only probes the official UUP dump API with a bounded timeout.

`RunPreflight` aggregates independent problems and returns `success=true`, `data.ready=false` when the BuildPlan is valid but the environment is not ready. Local preflight runs before UAC; the elevated worker repeats authoritative preflight before the build.

## Structured errors

Error codes are assigned at the source failure using the existing `New-WibErrorException`/`Exception.Data` mechanism, without parsing localized messages.

Added codes: `UNSUPPORTED_HOST`, `REQUIRED_COMPONENT_MISSING`, `PATH_NOT_WRITABLE`, `DISK_SPACE_LOW`, `NETWORK_ERROR`, `UUP_PACKAGE_DOWNLOAD_FAILED`, `UUP_PACKAGE_INVALID`, `DOWNLOAD_FAILED`, `CONVERTER_FAILED`, `DISM_FAILED`, `ISO_NOT_FOUND`, `ISO_VALIDATION_FAILED`, `ELEVATION_CANCELLED`, `BUILD_CANCELLED`.

Optional `error.details` carries controlled data such as path/bytes/component/exitCode/targetRequestId.

## Cancellation

`ExecuteBuildPlan.requestId` is the operation id. `CancelBuild` accepts `targetRequestId` and `cacheDirectory` and creates `<cache>\control\<SHA256(requestId)>.cancel.json`.

The raw request id is never used as a path. Existing markers are not deleted during worker initialization, so early cancellation is not lost. Request ids must be unique per execution.

`CancelBuild` acknowledgement does not mean the target is already stopped. The target confirms cancellation with `BUILD_CANCELLED` and a `cancelled` event.

## Elevation and child processes

Cancellation hash/cache context is forwarded to the elevated child separately from BuildPlan. BuildPlan Schema v1 does not acquire runtime control fields.

The UUP batch runs through a managed runner. On cancellation it terminates only the process tree rooted at a PID created by Windows ISO Builder using Windows `taskkill /PID <pid> /T /F`. Kill-by-name is not used.

Existing compact console progress, structured progress, and converter/build/elevated/execution logs remain available.

## Cache/resume

Cancellation does not delete UUP package/cache data, the work directory, aria2 partial state, or converter logs. A later operation with a new request id and the same BuildPlan can use normal resume behavior.

## Tests

Mock-based Pester tests cover preflight aggregation, error taxonomy, safe cancellation paths, race behavior, cancelled state/events, cache preservation, and managed process ownership. A separate Windows process-tree smoke is opt-in and uses a controlled dummy PowerShell process rather than aria2/DISM.

Before release, run locally:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
Invoke-ScriptAnalyzer -Path . -Recurse -Settings .\.psscriptanalyzer.psd1
```

`GetVersion`, `RunPreflight`, and controlled cancellation smokes through `Invoke-WibBackend.ps1` are also required; repeat safe smokes in PowerShell 7 when `pwsh` is available.

## Not included

GUI/WPF/WinUI, C#, installer/updater, queue/history/profiles, USB/Rufus, dynamic disk estimation, custom UUP API/downloader/converter, GitHub Actions, and a full Windows E2E matrix.
