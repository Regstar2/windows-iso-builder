# Windows ISO Builder v0.2.2-alpha.1 — Reliability & Control

Дата: 2026-08-18

## Назначение

`v0.2.2-alpha.1` — второй архитектурный релиз перед GUI. Он не добавляет GUI и не меняет Backend Contract/BuildPlan SchemaVersion. Цель — сделать существующий backend достаточно предсказуемым для frontend, который должен заранее диагностировать environment и безопасно отменять долгую сборку.

## Версии

- ApplicationVersion: `0.2.2-alpha.1`;
- ModuleVersion: `0.2.2`;
- Backend Contract SchemaVersion: `1`;
- BuildPlan SchemaVersion: `1`.

## Preflight

Добавлен reusable `Invoke-WibPreflight`, который используется и `RunPreflight`, и реальной build operation.

Local checks включают Windows/x64/PowerShell, required tools, cache/output path/write probes и conservative disk minimums 40 GiB/8 GiB. `Mount-DiskImage` является warning. Optional online check проверяет только официальный UUP dump API с ограниченным timeout.

`RunPreflight` агрегирует независимые проблемы и возвращает `success=true`, `data.ready=false`, если BuildPlan корректен, но environment не готов. Local preflight выполняется до UAC; elevated worker повторяет проверку перед build.

## Structured errors

Error codes теперь назначаются у source failure через existing `New-WibErrorException`/`Exception.Data`, без parsing localized message.

Добавлены `UNSUPPORTED_HOST`, `REQUIRED_COMPONENT_MISSING`, `PATH_NOT_WRITABLE`, `DISK_SPACE_LOW`, `NETWORK_ERROR`, `UUP_PACKAGE_DOWNLOAD_FAILED`, `UUP_PACKAGE_INVALID`, `DOWNLOAD_FAILED`, `CONVERTER_FAILED`, `DISM_FAILED`, `ISO_NOT_FOUND`, `ISO_VALIDATION_FAILED`, `ELEVATION_CANCELLED`, `BUILD_CANCELLED`.

Optional `error.details` передаёт controlled data вроде path/bytes/component/exitCode/targetRequestId.

## Cancellation

`ExecuteBuildPlan.requestId` является operation id. `CancelBuild` принимает `targetRequestId` и `cacheDirectory` и создаёт marker `<cache>\control\<SHA256(requestId)>.cancel.json`.

Raw request id не используется как path. Existing marker не удаляется при worker initialization, поэтому early cancel не теряется. Request id должен быть уникальным для каждой execution.

`CancelBuild` acknowledgement не означает, что target уже остановлен. Target подтверждает отмену через `BUILD_CANCELLED` и `cancelled` event.

## Elevation and child processes

Cancellation hash/cache context передаётся elevated child отдельно от BuildPlan. BuildPlan Schema v1 не получает runtime control fields.

UUP batch запускается managed runner. При cancel он завершает только process tree с PID, созданным Windows ISO Builder, через Windows `taskkill /PID <pid> /T /F`. Kill-by-name не используется.

Existing compact console progress, structured progress, converter/build/elevated/execution logs сохраняются.

## Cache/resume

Cancellation не удаляет UUP package/cache, work directory, aria2 partial state или converter logs. Повторная операция с новым request id и тем же BuildPlan может использовать normal resume.

## Tests

Добавлены mock-based Pester tests для preflight aggregation, error taxonomy, safe cancellation path, race behavior, cancelled state/events, cache preservation и managed process ownership. Отдельный Windows process-tree smoke test является opt-in и использует dummy PowerShell process вместо aria2/DISM.

Перед выпуском должны быть выполнены локально:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
Invoke-ScriptAnalyzer -Path . -Recurse -Settings .\.psscriptanalyzer.psd1
```

Также требуются `GetVersion`, `RunPreflight` и controlled cancellation smokes через `Invoke-WibBackend.ps1`; при наличии `pwsh` безопасные smoke tests повторяются в PowerShell 7.

## Не входит в релиз

GUI/WPF/WinUI, C#, installer/updater, queue/history/profiles, USB/Rufus, dynamic disk estimator, custom UUP API/downloader/converter, GitHub Actions и full Windows E2E matrix.
