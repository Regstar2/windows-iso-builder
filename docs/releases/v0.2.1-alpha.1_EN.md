# Windows ISO Builder v0.2.1-alpha.1 — Backend Contract

Date: 2026-08-18

## Release purpose

`v0.2.1-alpha.1` is an architectural release preparing the project for a future GUI. It adds a stable machine-readable contract over the existing PowerShell backend without rewriting the build pipeline or creating a frontend-specific duplicate backend.

A GUI is **not implemented** in this release.

## Highlights

- Backend Contract Schema v1;
- dedicated ASCII-only `Invoke-WibBackend.ps1` machine entry point;
- UTF-8 JSON request/response files;
- optional UTF-8 NDJSON event stream;
- stable machine-oriented error codes;
- controlled DTO boundary with English camelCase properties;
- reusable quick-mode recommendation logic shared by the TUI and future frontends;
- structured progress produced by the existing converter parser;
- event forwarding through the existing elevated plan/result protocol;
- one runtime ApplicationVersion source in `VERSION`;
- Windows PowerShell 5.1 and PowerShell 7 remain compatibility targets.

## Error codes v1

`INVALID_REQUEST`, `UNSUPPORTED_SCHEMA`, `INVALID_COMMAND`, `INVALID_ARGUMENT`, `BUILD_NOT_FOUND`, `LANGUAGE_NOT_FOUND`, `EDITION_NOT_FOUND`, `UUP_API_ERROR`, `UUP_API_UNAVAILABLE`, `INVALID_BUILD_PLAN`, `ELEVATION_FAILED`, `BUILD_FAILED`, `INTERNAL_ERROR`.

Additional error codes may be introduced within schema v1 without a breaking schema change.

## Progress/events

Structured events carry `requestId`, monotonic `sequence`, ISO-8601 timestamp, type, normalized stage, and a progress object. Core event types are `stage`, `progress`, `completed`, and `failed`; `warning` and `info` are also permitted.

Normalized stages: `startup`, `catalog`, `metadata`, `plan`, `preflight`, `download`, `convert`, `verify`, `completed`, `failed`.

Raw aria2 output is not contract data. A single parser in `ConsoleProgress.ps1` feeds both the console renderer and the structured event sink.

## Compatibility

Preserved by design:

- `Start-Builder.cmd` and `Start-Builder.ps1`;
- interactive TUI;
- non-interactive CLI;
- quick mode;
- UUP dump catalog/workflow;
- BuildPlan Schema v1;
- UAC/elevation;
- UUP converter/aria2/DISM pipeline;
- console progress;
- logs;
- caching/resume behavior;
- no hardcoded Windows build/release catalog.

## Security

Backend requests are untrusted input. Command dispatch is restricted to an allowlist; `Invoke-Expression`/eval are not used; JSON is never executed as code. Contract DTOs must not expose signed UUP URLs, product keys, tokens, arbitrary Exception graphs, or private PowerShell metadata.

## Deliberately out of scope

GUI/WPF/WinUI, C# rewrite, updater, USB/Rufus integration, queue/history/profiles, cache GUI, a full cancellation subsystem, the next release's full preflight layer, complete error taxonomy, a custom UUP downloader/converter, and GitHub Actions.

## Verification before release

Before an actual release/tag, run:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
Invoke-ScriptAnalyzer -Path . -Recurse -Settings .\.psscriptanalyzer.psd1
```

Also run a `GetVersion` smoke test through `Invoke-WibBackend.ps1` in Windows PowerShell 5.1 and, when available, PowerShell 7.

Backend Contract Pester tests use mocks and do not download Windows.
