# v0.2.3-alpha.1 — Validation & Release Hardening

Date: 2026-08-18

## Purpose

This is the final backend-focused release before `v0.3.0` GUI work begins. It does not expand user-facing feature scope. The goal is to make the existing PowerShell backend reproducibly verifiable, protect Backend Contract v1 / BuildPlan v1 from accidental breaking changes, and validate the release ZIP as a user receives it.

GUI, WPF/WinUI, and C# are intentionally absent.

## Added

- unified `tools/Invoke-ReleaseValidation.ps1` with Quick/Full and opt-in smoke layers;
- machine-readable `validation-result.json` and deterministic exit status;
- centralized `tools/ReleasePackageConfig.psd1` logical allowlist/denylist;
- shared release-validation helpers;
- semantic Backend Contract v1 compatibility regression tests;
- regression protection for all ten existing Backend commands;
- required success/error envelope regression;
- build/preflight/build-result/progress/cancelled DTO/event regression;
- controlled failure-injection coverage for structured error codes;
- `tests/fixtures/build-plan-v1.json` plus a small GetVersion request fixture;
- BuildPlan v1 read/validate/round-trip regression;
- generated `release-manifest.json` inside package staging;
- release ZIP checksum/open/content/manifest validation;
- extracted-package module/backend smoke with source-checkout leakage protection;
- limited current tracked-tree/package scan for obvious secrets, private-key blocks, credential assignments, personal absolute paths, and generated junk;
- RU/EN validation matrix and a manual E2E result template.

## Changed

- `tools/New-ReleasePackage.ps1` now uses the shared release manifest configuration and validates staging before creating the ZIP;
- source validation and release-package validation are explicitly separate;
- VERSION is `0.2.3-alpha.1`, ModuleVersion is `0.2.3`;
- Backend Contract SchemaVersion remains `1`;
- BuildPlan SchemaVersion remains `1`;
- Backend Contract v1 / BuildPlan v1 are documented as the first-GUI baseline;
- documentation separates Implemented, Automated-ready, Confirmed, Not run, and Not required claims;
- generated `dist/` and `validation-result*.json` are ignored by Git.

## Validation workflow

Quick:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Invoke-ReleaseValidation.ps1
```

Full safe release validation:

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Invoke-ReleaseValidation.ps1 -Full
```

The normal validation workflow never downloads a UUP set, builds a real ISO, or requires UAC.

Full validation additionally covers the release ZIP, strict PSScriptAnalyzer policy, PowerShell 7 when available, and controlled PID-tree cancellation using dummy PowerShell processes.

## Release package

The package contains a generated `release-manifest.json` with application/module/contract/build-plan versions only. It contains no timestamp, username, machine name, local path, or secrets.

Package smoke extracts into Temp and imports the module from the package root rather than the source checkout.

## Contract compatibility

Schema v1 baseline commands:

`GetVersion`, `SearchBuilds`, `GetRecommendedBuild`, `GetLanguages`, `GetEditions`, `CreateBuildPlan`, `ValidateBuildPlan`, `ExecuteBuildPlan`, `RunPreflight`, `CancelBuild`.

Tests protect the required semantic contract without rejecting additive optional fields. A breaking rename/removal/semantic change after this baseline requires SchemaVersion 2.

## Real E2E status

- Windows 11 x64, ru-RU, Core + Professional, ESD: **Confirmed baseline from the preserved pipeline**, not a new v0.2.3 run;
- Windows 10 x64, Professional, ESD: **NOT RUN**;
- Windows 11 x64, single edition, WIM: **NOT RUN**.

No `NOT RUN` scenario is represented as a simulated PASS. Procedures are documented in `docs/VALIDATION_MATRIX_EN.md`.

## Compatibility

- Backend Contract SchemaVersion: `1`;
- BuildPlan SchemaVersion: `1`;
- TUI/CLI/quick mode unchanged by design;
- Windows PowerShell 5.1 remains a mandatory target;
- PowerShell 7 remains an optional compatible runtime;
- WIM/ESD, virtual editions, cache/resume, UAC/elevation, progress/logging, and cancellation mechanisms are not rewritten.

## GUI integration boundary

The future GUI must use only `Invoke-WibBackend.ps1`, Backend Contract v1, BuildPlan v1, `RunPreflight`, `ExecuteBuildPlan`, `CancelBuild`, request ids, NDJSON events, and structured error codes.

Private PowerShell functions, console text, aria2 output, and localized error messages are not GUI APIs.

## Scope intentionally absent

GUI, WPF, WinUI, C#, installer, MSIX, updater, history, profiles, queue, USB writer, Rufus integration, dynamic disk estimation, driver injection, customization/debloat, TPM bypass, activation, custom UUP downloader/converter, and GitHub Actions.
