# Windows ISO Builder v0.3.1 — GUI Polish

## Goal

`v0.3.1` polishes the WPF GUI without changing Backend Contract v1 or moving UUP/build ownership out of the PowerShell backend.

Quick Mode is no longer a long page-level scrolling form. Windows selection, parameters, compact preflight state, and a persistent build/status area share one responsive layout; progress and cancellation stay in the persistent bottom region.

## UI layout

- `Quick / Catalog` is visually exposed only in the left navigation;
- the internal `TabControl` remains only as a page container with hidden non-focusable headers;
- Quick Mode has no page-level `ScrollViewer`;
- parameters and preflight use a two-column grid;
- edition collection scrolling is confined to the collection itself;
- advanced options and full preflight details use separate WPF dialogs;
- the Catalog `DataGrid` owns its own scrolling and fills available height;
- the selected-build action row remains visible;
- the persistent build panel switches between `idle / progress / error / result / cancelled` states without appending content below the viewport.

Target working size is `1100×700 DIP`; minimum size is `960×600 DIP`.

## Theme and DPI

The GUI uses WPF `ThemeMode="System"`; the application manifest declares `PerMonitorV2` DPI awareness. Layout remains based on WPF device-independent pixels rather than manual coordinate scaling.

## Localization

Supported UI locales are `en` (base/fallback) and `ru`. Fallback is requested locale → language family → `en`. Unsupported system locales use English. The footer language selector persists the explicit choice.

Product/data values such as `Windows 11`, `WIM`, `ESD`, architecture identifiers, build numbers, paths, hashes, and backend codes are not translated.

## Accessibility and keyboard

Major controls expose localized UI Automation names where native labels are insufficient. Localized tooltips explain Preview, servicing entries, WIM/ESD, advanced options, preflight, and diagnostics. Hidden tab headers do not participate in keyboard focus; the main workflow uses natural WPF focus order.

## Window settings

`%LOCALAPPDATA%\WindowsISOBuilder\settings.json` stores normal window bounds, maximized state, and selected UI locale. Malformed settings do not block startup. Saved bounds are used only when the window materially intersects a current monitor work area; `Minimized` is never persisted as a startup state.

## Diagnostics

`Create diagnostics package` creates a ZIP with exactly:

```text
app-version.txt
environment.json
execution.log
build.log
converter.log
```

`environment.json` uses an allowlist. Logs are sanitized before ZIP writes. A shared `DiagnosticSanitizer` replaces HTTP/HTTPS URLs, user-profile paths, usernames, bearer/token/API-key/secret assignments, and Windows product keys. Raw directories are never archived with `CreateFromDirectory`.

## Compatibility

Backend Contract SchemaVersion `1`, BuildPlan SchemaVersion `1`, PowerShell backend ownership, the WPF-only boundary, headless smoke without `StartupUri`, one-way read-only progress binding, and transport/process safety boundaries remain unchanged.

GUI assembly/file version is raised to `0.3.1`; `AssemblyVersion` remains `0.3.0.0`. Root release `VERSION` and PowerShell ModuleVersion are intentionally unchanged until a separate release/versioning step.

## Automated coverage

Coverage is added/extended for layout invariants, hidden tab navigation, system theme/PerMonitorV2, RU/EN resource and placeholder parity, English fallback, diagnostics sanitization/ZIP entry set, and settings round-trip/off-screen rejection. Actual CI and manual GUI/DPI/Narrator results are reported separately.
