# v0.3.2 — Navigation, settings and help

## Цель

Упростить оболочку GUI после ручной приёмки v0.3.1: освободить место под рабочие страницы, убрать служебные элементы из нижней панели, добавить отдельные разделы настроек/помощи и сделать основной сценарий сборки визуально последовательным.

## Изменения

- верхний внутренний header Windows ISO Builder удалён; название и версия перенесены в левую навигацию;
- раздел «Быстрый» переименован в «Сборка»;
- навигация содержит «Сборка», «Каталог», «Настройки», «Помощь» и «О приложении» без большого пустого разрыва между группами;
- строка состояния перенесена в нижнюю панель рядом с `UUP dump / Microsoft CDN`;
- язык интерфейса, тема и создание диагностического пакета перенесены в «Настройки»;
- добавлен выбор темы: как в Windows, светлая, тёмная; явная тёмная тема применяет отдельную тёмную палитру оболочки, а выбор сохраняется;
- «О приложении» показывает описание, версию и ссылку на GitHub;
- «Помощь» содержит краткий сценарий создания ISO, описание каталога и действия при ошибке;
- строка фильтров каталога теперь адаптивная: элементы переносятся на следующую строку вместо исчезновения кнопки «Найти» при уменьшении доступной ширины;
- таблица каталога допускает горизонтальную прокрутку при узком окне;
- основной сценарий «Сборка» подсвечивает системным accent color только следующий требуемый шаг: «Получить рекомендуемую» → выбор редакции → «Проверить готовность» → «Создать ISO»;
- если сборка выбрана из каталога, шаг «Получить рекомендуемую» автоматически пропускается и подсветка начинается с выбора редакции.

## Совместимость

Backend Contract, PowerShell backend, BuildPlan и процесс сборки ISO не изменяются. GUI assembly/file version повышена до `0.3.2`; root ApplicationVersion и ModuleVersion остаются без изменений до отдельного release/versioning шага.

## Проверка

Автоматические проверки должны подтвердить сборку WPF, RU/EN parity, старт на странице «Сборка», новую структуру навигации, сохранение темы, адаптивную строку фильтров каталога и наличие последовательной workflow-подсветки. Визуальная проверка реального GUI остаётся обязательной перед merge.
