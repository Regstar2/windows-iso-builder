## О проекте

Windows ISO Builder проводит пользователя через поиск сборки Windows, выбор архитектуры, языка, редакций и формата установочного образа. Каталог версий не хранится в исходном коде: данные запрашиваются у UUP dump, а файлы Windows загружаются с Microsoft Windows Update/CDN.

Техническое имя репозитория и корневого каталога — `windows-iso-builder`. Публичное название продукта — Windows ISO Builder.

Проект не заменяет UUP dump и не реализует собственный UUP-движок. Его задача — сократить ручной процесс до одного интерактивного сценария.

## Статус проекта

Текущая версия — **`0.2.0-alpha.1`**.

Это публичная alpha: основной сценарий работает, локальные автоматические проверки проходят, а реальная end-to-end сборка Windows 11 x64 ru-ru подтверждена до готового ISO. Проект пока не позиционируется как стабильный релиз и не обещает, что каждая возможная версия Windows, редакция и комбинация параметров прошла отдельный ручной тест.

Подробная матрица подтверждённых и непроверенных сценариев находится в [статусе реализации](docs/IMPLEMENTATION_STATUS.md).

## Возможности

- динамический поиск по названию релиза, номеру сборки или заголовку UUP dump;
- быстрый выбор рекомендуемой стабильной Windows 11 или Windows 10 x64 без просмотра каталога и без зашитого номера сборки;
- для Windows 11 quick mode предпочитает массовый стабильный `YYH2`-релиз специализированным H1-веткам, если подходящий H2 доступен;
- постраничный просмотр больших результатов поиска с переходом вперёд, назад и к нужной странице;
- отсутствие фиксированного каталога поддерживаемых версий Windows;
- фильтры `x64`, `ARM64` и `x86`, Preview/Insider скрыты по умолчанию;
- динамическая загрузка языков и редакций выбранной сборки;
- выбор одной или нескольких редакций через virtual editions конвертера UUP dump;
- создание `install.esd` или `install.wim`;
- кеширование API, конвертационного пакета и UUP-файлов;
- повторное использование уже загруженных файлов и штатное продолжение незавершённых загрузок средствами `aria2`;
- компактная полоса прогресса загрузки/конвертации вместо непрерывного вывода `aria2`; полный вывод сохраняется в `converter-*.log`;
- структурированная передача результата elevated-процесса родителю вместо общего `Exit code: 1`;
- отдельные execution/elevated/converter/build-логи;
- SHA-256 и JSON-метаданные результата;
- проверка структуры ISO через `Mount-DiskImage` и DISM;
- интерактивный TUI и неинтерактивный режим PowerShell.

## Быстрый старт

1. Скачайте исходники или release ZIP и распакуйте их в локальный каталог.
2. Запустите `Start-Builder.cmd`.
3. Для обычного режима выберите `Найти сборку и создать ISO`; для рекомендуемого стабильного выпуска выберите `Быстро скачать последнюю Windows`.
4. В быстром режиме выберите Windows 11 или Windows 10 — приложение обновит каталог и автоматически определит рекомендуемую стабильную x64-сборку.
5. Выберите язык, редакции и формат образа.
6. Подтвердите UAC перед загрузкой и конвертацией.

Готовые файлы сохраняются в `output/`. Постоянный рабочий кеш по умолчанию расположен в `C:\UUP-ISO-Work`.

## Требования

- Windows 10 или Windows 11 x64;
- Windows PowerShell 5.1 или PowerShell 7;
- права администратора на этапе загрузки и конвертации;
- не менее 35–50 ГБ свободного места;
- доступ к UUP dump и Microsoft Windows Update/CDN.

## Использование

В интерактивном режиме программа сначала собирает параметры и только затем запрашивает повышение прав. Это позволяет отменить или изменить выбор до начала длительной операции.

Быстрый режим пропускает ручной просмотр каталога. Для выбранного семейства Windows 11 или Windows 10 он запрашивает свежий каталог UUP dump, оставляет только стабильные полноценные x64-сборки и выбирает рекомендуемый вариант динамически. Конкретный номер выпуска или сборки в production-коде не фиксируется.

Для Windows 11 массовый стабильный H2-релиз имеет приоритет перед специализированным H1 с большим номером. Если подходящего H2 нет, приложение использует лучшую стабильную полноценную сборку и показывает предупреждение.

Во время выполнения `uup_download_windows.cmd` подробные строки `aria2` и конвертера не печатаются непрерывно в консоль. Приложение показывает одну обновляемую полосу с текущим этапом, процентом загрузки и скоростью, когда эти данные доступны. Полный исходный вывод конвертера сохраняется рядом с журналом сборки в `output/logs/converter-*.log`.

Каталог различает полноценные записи Windows и служебные пакеты обновлений. По умолчанию `.NET`, cumulative, OOBE и другие servicing-записи скрыты, чтобы их нельзя было случайно выбрать как источник ISO.

Повторный запуск с той же сборкой, языком и базовой редакцией использует существующий рабочий каталог. `aria2` проверяет загруженные файлы и использует свои штатные механизмы продолжения незавершённой загрузки. Отдельный тест с принудительным обрывом сети не является release gate для `0.2.0-alpha.1`.

## Команды

Неинтерактивный пример:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Builder.ps1 `
  -NonInteractive `
  -Search 22H2 `
  -Architecture amd64 `
  -Language ru-ru `
  -Editions Core,Professional `
  -ImageFormat ESD
```

В этом режиме при наличии подходящих записей предпочтение отдаётся полноценной сборке Windows, а не cumulative/.NET/OOBE-пакету. Прямой выбор UUID пока не реализован.

## Архитектура

PowerShell-модуль разделяет работу с API, кешем, выбором параметров, формированием плана и запуском конвертера. Подробное описание находится в [документе архитектуры](docs/ARCHITECTURE.md).

## Безопасность

Программа не должна отключать антивирус, UAC или глобальную политику выполнения PowerShell. Пакет UUP dump запускается только после проверки структуры ZIP и распаковывается в принадлежащий программе рабочий каталог.

В публичные отчёты нельзя включать полные UUP-ссылки, ключи продукта, токены и персональные пути. Порядок сообщения об уязвимостях описан в [SECURITY.md](SECURITY.md).

## Диагностика

После ошибки программа сохраняет журнал и показывает путь к нему. При проблемах необходимо проверить:

1. доступность UUP dump и Microsoft CDN;
2. свободное место на системном и рабочем дисках;
3. отсутствие блокировки `aria2`, DISM или конвертера антивирусом;
4. `build-*.log`, `converter-*.log`, execution-log и elevated-log конкретного запуска.

## Сборка

Проект не требует компиляции. Исходный код запускается через `Start-Builder.cmd` или `Start-Builder.ps1`. PowerShell-модуль находится в `src/WindowsISOBuilder/`.

## Тестирование

Проект использует **локальные** Pester-тесты и PSScriptAnalyzer. GitHub Actions не являются частью процесса проверки или выпуска.

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-Tests.ps1
Invoke-ScriptAnalyzer -Path . -Recurse -Settings .\.psscriptanalyzer.psd1
```

Локальные тесты проверяют логику и совместимость, но не заменяют реальную сборку ISO. Для `0.2.0-alpha.1` подтверждён реальный end-to-end сценарий Windows 11; Windows 10 и полная матрица WIM/ESD не являются обязательными alpha release gates.

## Происхождение и благодарности

UUP dump предоставляет каталог, метаданные и пакет конвертации. Файлы Windows загружаются средствами этого пакета с серверов Microsoft Windows Update/CDN.

Проект не связан с Microsoft, не распространяет готовые ISO Windows, не активирует Windows и не обходит лицензирование.

## Ограничения

- `0.2.0-alpha.1` — ранняя версия, а не стабильный релиз;
- реальный end-to-end Windows 10 не входит в обязательную проверку этой alpha;
- отдельный принудительный тест восстановления после обрыва сети не проводился как release gate;
- WIM и ESD поддерживаются, но полная ручная матрица обоих форматов не является release gate;
- совместимость комбинаций virtual editions зависит от выбранной базовой редакции и версии конвертера UUP dump;
- внешний API и формат конвертационного пакета могут измениться;
- GUI и автоматическое обновление приложения отсутствуют;
- в неинтерактивном режиме пока нельзя указать UUID напрямую.
